# Команда 1 — 2-3 дерево

## Реализация

Исходный код: [`team1_23_tree.cpp`](team1_23_tree.cpp). В узле хранится 1 или 2 ключа; внутренний узел имеет 2 или 3 ребёнка. Дубликаты игнорируются. Поддерживаются вставка, поиск, удаление, печать высоты/числа узлов/расщеплений/слияний/перераспределений.

В формулировке задания есть неоднозначность: по приведённой формуле B-дерева при `t=2` разрешено до `2t−1=3` ключей, то есть получается 2-3-4 дерево. Для команды 1 реализовано классическое 2-3 дерево: максимум 2 ключа в узле. Команда 3 отдельно указана как 2-4 дерево.

## Наборы и методика

В `sem11.txt` определены три набора по 10 000 операций:

- **Random:** `rand() % 100000`.
- **Sorted:** целые числа от 1 до 10 000.
- **Hotspot:** 5 000 раз ключ `42`, затем 5 000 случайных чисел `rand() % 100000`.

Для воспроизводимости генератор C запускается с `srand(1)` отдельно для Random и Hotspot. Повторные вставки не создают дубликаты. Поиск выполняется по исходным 10 000 значениям. Удаление также вызывается для всех значений исходного набора; повторное удаление уже отсутствующего ключа ничего не меняет. Время — медиана семи запусков, сборка `c++ -std=c++17 -O2`. Тайминги зависят от компьютера и компилятора.

## Интерпретация и асимптотика

Все листья находятся на одной глубине. Поэтому сортированный вход не превращает дерево в цепочку: высота осталась 13 при 10 000 уникальных ключах. При вставке каждый ключ проходит один путь от корня, поиск проходит не более одного пути, удаление также занимает логарифмическое время. Для 2-3 дерева все три операции имеют худшую оценку `O(log n)`; обход всех ключей — `O(n)`, память — `O(n)`.

Сортированный набор вызвал больше расщеплений, потому что вставки постоянно нагружают правый край дерева. В Hotspot всего 4 879 уникальных ключей, поэтому высота и число расщеплений ниже. Слияния происходят при удалении, когда сосед не может отдать ключ; перераспределение позволяет избежать слияния. Счётчики показывают, что для Sorted в этом порядке удаления почти все исправления прошли через слияния, а для Random и Hotspot заметно чаще удавалось перераспределить ключ.

## Сравнение с командой 4 (B+ дерево, t=3)

| Свойство | Команда 1: 2-3 дерево | Команда 4: B+ дерево, t=3 |
|---|---|---|
| Где лежат значения | Во внутренних узлах и листьях | Только в листьях; внутренние ключи — копии-разделители |
| Максимум ключей / детей | 2 ключа / 3 ребёнка | По шаблону задания: 5 ключей-разделителей / 6 детей; в листе до 5 ключей |
| Поиск ключа | Может завершиться во внутреннем узле | Всегда доходит до листа |
| Диапазонный запрос | Нужен обход дерева, `O(log n + k)` при последовательном обходе | Связанные листья дают `O(log n + k)` и удобный последовательный проход |
| Высота | 11–13 уровней на тестах | Обычно ниже за счёт большего ветвления |

B+ дерево имеет больший фактор ветвления, поэтому при сопоставимой заполненности обычно ниже по высоте. Связанные листья упрощают последовательный проход по диапазону: после поиска первого элемента можно читать соседние листья без возврата к корню.

### Вывод для совместной защиты

Для точечного поиска и обновления оба сбалансированных дерева дают `O(log n)`. B+ дерево лучше подходит для диапазонных запросов и последовательного чтения благодаря связанным листьям и большему числу потомков. 2-3 дерево проще по устройству и может закончить поиск во внутреннем узле. Выбор зависит от нагрузки: для диапазонов и индексирования больших наборов предпочтительно B+ дерево; для учебной реализации сбалансированного поиска достаточно 2-3 дерева.

## Запуск

```sh
bash run_tests.sh
```

Скрипт собирает программу, выполняет 30 000 случайных вставок и удалений, проверяет инварианты дерева и сравнивает его содержимое с `std::set`, затем запускает три набора и печатает CSV.
